# SPOKE_INIT retired

This skill is a historical compatibility tombstone. It is retained so old
spoke-projection artifacts and documentation can be identified, but it is not
a current CStar route and it does not authorize a link, project, scan, worker,
provider, profile, transport, Hall mutation, Git action, or filesystem write.

The current v3 host workflow is Codex-host Luna with requested selector
`gpt-5.6-luna` and reasoning `max`. Actual identity remains unreported unless
the host supplies a distinct attestation. MM is inactive and has no active
routing, synthesis, ownership, relay, review, or execution role.

## Historical boundary

Older versions described a deterministic spoke projector and optional host
augmentation that could produce artifacts such as:

- `<spoke>/.cstar/SPOKE_PROFILE.md`;
- `<spoke>/.cstar/spoke_profile.json`;
- `<spoke>/.cstar/IDENTITY.json` and `<spoke>/.cstar/CSTAR_CONTRACT.md`; and
- bounded capability, intake, and acknowledgement documents.

Those names are historical evidence labels only. Their presence does not prove
that a spoke is linked, current, trusted, ready, enrolled, or authorized for a
lifecycle transition. Historical Hall projection fields and mount-token
records likewise grant no authority and must not be treated as current
readiness.

Historical Hermes/MiniMax profile references are readable only as explicitly
labeled legacy v2 compatibility history. They are never a current transport,
provider, ownership source, fallback, or optional substitution for the
Codex-host v3 handoff.

## Fail-closed contract

- Do not read private Hermes or MiniMax profiles, OAuth state, credentials,
  provider metadata, or transport selectors.
- Do not spawn a host model, provider, subprocess, network request, or child
  skill from this surface.
- Do not write spoke files, Hall/SQLite state, receipts, lifecycle state,
  Git state, or activation artifacts from this surface.
- Do not infer readiness, authority, ownership, actual model identity, or
  current transport from a registry, manifest, cached profile, or historical
  projection.
- Route any current spoke operation through the supported CStar kernel
  surface and its explicit operator gates; this compatibility file cannot
  replace that lifecycle.

The retired surface therefore has no current execution steps or readiness
check. A historical artifact may be reviewed as bounded evidence, then must be
validated independently before any separate authorized workflow proceeds.
